# 方法与判据

## 本题的工作流程

1. 读申报要求（模板、字数、评审要点、预算科目），写成 `requirements.json` 并逐条做覆盖表。
2. 抽取前期基础（已有数据、预实验、团队条件），每条带来源定位；没有来源的经历不写。
3. 按评审要点组织：问题与意义 / 现状与缺口 / 目标与创新 / 技术路线（含里程碑） / 可行性 / 风险与备选 / 预期成果 / 预算说明。
4. 风险段必须给“风险 → 判据 → 备选方案”，不能只写“风险可控”。
5. 字数与格式机械自检（字数、章节齐全、引用格式），超限处做删减而非压缩事实。
6. 输出可编辑件 + 覆盖表（每条评审要点 → 所在章节）。

## 交付前自检清单

- 评审要点全覆盖且有定位
- 前期基础均有来源
- 风险给判据与备选
- 字数/格式合规
- 无来源的个人经历未出现

## 定位符约定

- PDF：`p<页>b<块>`（块号在同一页内从 1 递增，由 `pdf_text.py` 生成）
- 纯文本：`<文件名>:<行号>` 或 `<文件名>:<段落号>`
- 代码/配置：`<文件>:<行号>`
- 引语核验：`evidence.py verify blocks.json quotes.json`，`exact=true` 才可作为逐字证据
