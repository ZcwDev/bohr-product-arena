# 使用增益（同输入 · 同模型 · 真跑对照）

同一组输入（2 题 + 2 候选 + 参考 + 两份评分员记录）：
**A = 不加载 Skill**（直接交给 `qwen4-max` 要求打分 + 一致性）；**B = 本 Skill**。
A 的原始回答在 `example/baseline.txt`。

| 指标 | A（无 Skill） | B（有 Skill） |
|---|---|---|
| 逐题分数 | 有（W1 0.4 / W2 0.3333，归一化到 0–1） | 有（W1 2.0/5.0、W2 2.0/3.0，按 rubric 权重，可解释） |
| 失败类型 | 有（`missing_Limitations`、`accuracy_rejected_claim`） | 有（`wrong_format`、`wrong_fact` + 每条锚点的 `why`） |
| 一致性统计 | 有（completeness 100%/κ=null、accuracy 50%/κ=0） | 有（同值，且对 n<2 的判据显式给 `null`） |
| **每条判据的扣分理由** | **无**（只有失败标签） | **有**（`criteria[].why`：缺哪一节 / 命中哪个 reject 片段） |
| **可追溯（输入哈希）** | **无** | 有（`run_record.inputs_sha256_16`） |
| **可复跑产物** | **无**（一段回答） | `result.json` + `per_item.tsv` + `report.md` + `SELFCHECK.json` |
| 改进建议 | 无 | 有（逐题："补上缺失小节" / "对照参考变体重写该处"） |

**结论（照实写）**
1. 这份小样本上，**A 的判定与一致性统计并不比 B 差**——所以增益不在"算得对"，而在
   **每条分数的可解释性（锚点级 why）、可追溯（哈希）、可复跑（产物）与改进建议**。
2. B 把"kappa=0"直接翻译成"该锚点不可观察，应改锚点而不是改分数"——这是 A 不会给出的动作。
3. **没有改善的地方**：语义级判断（事实是否真的与引用一致）两边都要靠人；本工具只做锚点级结构匹配。
