# 方法与判据

## 本题的工作流程

1. 解析审稿意见为条目 `R1.1, R1.2…`，每条抽核心诉求（要求做什么/质疑什么）。
2. 逐条分类：`clarification`（已做未说清）/ `text_fix`（表述与格式）/ `analysis`（可补的分析） / `new_experiment`（本轮做不到）/ `disagree`（有依据不接受）。
3. 可做的：改稿并给 `改前/改后` 片段 + 稿件定位；不可做的：写清理由 + 替代措施（现有数据重分析、加限制说明）。
4. 回应信逐条引用审稿原文（逐字），避免「我们已修改」式空答。
5. 一致性：回应信里承诺的每处修改都要在改稿里找到（`consistency.py check` 比对意见编号、change_log 与改稿原文）。
6. 输出 result.json：deliverable（回应信 + 改稿）+ change_log（逐条对应）。

## 交付前自检清单

- 审稿意见逐条编号且逐字引用
- 每条有分类与处置
- 未采纳给出了理由与替代
- 回应与改稿一一对应
- 无空泛回应

## 定位符约定

- PDF：`p<页>b<块>`（块号在同一页内从 1 递增，由 `pdf_text.py` 生成）
- 纯文本：`<文件名>:<行号>` 或 `<文件名>:<段落号>`
- 代码/配置：`<文件>:<行号>`
- 引语核验：`evidence.py verify blocks.json quotes.json`，`exact=true` 才可作为逐字证据
